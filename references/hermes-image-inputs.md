# Hermes Image Inputs

Use this reference on Hermes before a reference-based graphic. Keep the shared identity, one-office, visual acceptance and automatic-save rules unchanged.

## Verify the complete package

- Resolve the current installed skill root and run its reference verifier. Every file in the active six-image manifest must be present and byte-matched before declaring the installation ready.
- GitHub contains instructions and code, not the private image binaries. Obtain the approved private package through the authorized file connection. A missing non-office image might not explain an office API error, but it still means the installed package is incomplete.
- Keep the sole office base, four identity masters and non-office comparison in durable approved storage. Do not reactivate retired office views or rely on a scratch cache.
- If a native description-length constraint requires a shorter discovery description, adapt only that metadata and record the source version and transformation. Preserve the shared procedure and photograph exclusion.

## Check the actual image handoff

- Inspect the active image tool and distinguish its image provider/model from the conversation model.
- A tool accepting a local filename does not prove that the remote model received its contents. For an office request, preserve the stated base/body/face input order and require supported image-byte delivery for all three.
- Some Hermes FAL adapters advertise local paths but forward them unchanged when terminal execution is local. A remote service cannot read a server-local filename. An input download error containing those local paths identifies a transport failure, not a reason to rewrite Jack's appearance or drop the references.
- Use a verified native attachment adapter that safely reads permitted images, checks type/size and sends supported encoded image data before submission. Reject missing, invalid, oversized or protected files before the remote request. Keep image contents, encoded payloads and credentials out of ordinary output and public logs.
- Converting already-authorized files into the same provider's supported input format is transport handling, not an image-engine switch. It does not authorize repairing a runtime, installing tools, changing credentials or spending on another service during an ordinary graphic task. If the native adapter is broken, stop and obtain the required repair approval.
- Respect the current provider's documented reference limit, not only a stale local catalogue. Do not silently truncate away the face or body input. Preserve full office framing through the supported edit interface and inspect the actual output dimensions.
- Do not publish reference pictures or create public download links merely to satisfy a URL field. Embedded data still goes to the approved image service for processing; do not claim that it guarantees provider deletion or zero retention.

## Controlled tool repair and test

Runtime attachment fixes belong in the technical repository and approved deployment, not in a long drawing prompt. A source-only edit inside a disposable container is not a lasting fix. Keep the patch narrow, backed up and tied to the actual source version. Use the live deployment and approval mechanisms; never turn off skill safeguards to avoid a queue.

After an authorized repair, verify native discovery and run one real task on that agent with its existing image provider and own approved Drive connection. A temporary image-service mock proves only request construction, not generation quality or saving. Follow the shared attempt limit, review the actual image and verify the saved copy. A transport fix is not a visual-quality pass, and one Hermes result does not approve wider installation.

This link is technical source, not proof that another agent has installed it. Each target requires its own compatibility check and authorized rollout.
